# Repository roadmap

Planned implementation only. PRs remain scoped to this repository; dependencies are evidence gates, not permission to edit another owner.

## CG-01 - Lock fine-grained eviction matrix without relocating Program authority

Prerequisites: BASE-01, AG-01

1. Inventory generated-data, hydration, memory and autonomy executable call graphs.
2. Classify each file/function as generic donor, host adapter, normative policy, Program controller or historical.
3. Name beneficiary owner and preserve reference trace.
4. Reject directory-wide moves that steal leases/readiness from Program Execution.

**Acceptance:** Every affected surface has exactly one destination/retain/retire disposition. No generic runtime copied into two beneficiary repos.

**Required negatives:** Program-owned scheduler relocation outside scope is refused. Historical docs cannot be treated as live executable evidence.

## CG-02 - Project host policies and bind shared nodes

Prerequisites: CG-01, AG-06, ING-03, CTX-03

1. Move generic policy semantics to AgentOS profile/compiler/evaluator owner once.
2. Keep native host identity/result acceptance and safety gates local and thin.
3. Replace generic source processing and context hydration with owner capabilities.
4. Regenerate host docs/config through existing generators, not manual output edits.

**Acceptance:** Coding host can operate without importing donor generic runtime. Captured host result remains evidence, not auto-promoted memory.

**Required negatives:** Failed subagent return cannot appear completed. No direct memory provider fallback on node outage.

## CG-03 - Switch one writer and remove superseded generic paths

Prerequisites: CG-02, AG-07

1. Freeze old durable writer and inventory pending obligations.
2. Migrate bounded records with stable source and operation identities.
3. Confirm target parity/reconciliation before donor retirement.
4. Remove old imports/dead workers/config credentials after replacement receipt exists.

**Acceptance:** Exactly one authoritative writer per owned state surface after cutover. No acknowledged work or unresolved receipt is abandoned.

**Required negatives:** Rollback cannot re-enable donor writer against same workload. Removed runtime is not reintroduced by generated host synchronization.
