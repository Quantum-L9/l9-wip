# ADR-001: Fulfill context demand without copying cognitive compilation

**Repository:** Quantum-L9/l9-context  
**Date:** 2026-09-25  
**Status in pack:** LOCKED_REUSE_BOUNDARY  
**Implementation/deployment:** not performed by this delivery.

## Context
The existing cognitive runtime already defines demand and expected-plan validation.

## Decision
Context owns authenticated acquisition, cross-source evidence normalization, coverage, bounded fusion and deltas. Cognitive owner retains demand/compiler semantics.

## Alternatives not selected
Custom broker per agent; another kernel registry; direct Graphiti/source DB access.

## Ownership and invariants
The semantic owner is this repository only for the responsibility named above. Imported platform invariants retain their original owners. Read BOUNDARY.yaml and INVARIANTS.md before implementing. No adapter, registry index or profile may silently redefine this decision.

## Consequences
A ContextNeed can bind to owner ContextPlan. Final compile verifies demand identity; required coverage cannot be silently dropped.

## Required evidence
Changed plan triggers replan; missing required source remains explicit; optional unavailable source can degrade by policy. Unit-level negative tests, installed-artifact parity and staging proofs are required where applicable; pack checks cannot satisfy them.

## Migration and rollback
Invalidate stale bundles; keep lawful source evidence rather than invent replacement context.

## Provenance
Pinned l9-cognitive-runtime/docs/CONTEXT_PLANNING_BRIDGE.md. This record preserves locked direction while detailed schema/implementation proposals remain subject to owner contract acceptance. It is not a retrospective assertion that code has been merged or deployed.
